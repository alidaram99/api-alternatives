Content Moderator to Content Safety: what changes before 15 March 2027

Last updated: October 3, 2026

⏳ 163 days left — the old API shuts down March 15, 2027.

Microsoft points Content Moderator customers to Azure AI Content Safety, but it is not a new version of the same API. It uses a different endpoint (text:analyze), a different JSON body and a different taxonomy (Hate, Sexual, Violence and SelfHarm severities). PII, video and human review each move to a different Microsoft product, so every workflow needs its own migration decision (Microsoft migration guide).

Facts on this page were checked against the linked Microsoft Learn pages on October 3, 2026.

Which date? Microsoft gives two retirement dates:

  • Content Moderator's documentation says it "will be retired on March 15, 2027" (Microsoft Learn).
  • The lifecycle table lists April 1, 2027, 06:59 Pacific time (lifecycle).

Plan for the earlier date, and check the retirement notice for your own subscription.

If you would rather not rewrite the text-screening call before then, a wire-compatible Content Moderator replacement keeps ProcessText/Screen working with only a host and key change.

The two requests side by side

Content Moderator (retiring):

bash
curl -X POST "https://<region>.api.cognitive.microsoft.com/contentmoderator/moderate/v1.0/ProcessText/Screen?language=eng&classify=True&PII=True" \
  -H "Ocp-Apim-Subscription-Key: $KEY" -H "Content-Type: text/plain" \
  --data-binary 'Is this a crap email abcdef@abcd.com?'

Content Safety (Microsoft's replacement), per Microsoft's text quickstart:

bash
curl -X POST "<endpoint>/contentsafety/text:analyze?api-version=2024-09-01" \
  -H "Ocp-Apim-Subscription-Key: $KEY" -H "Content-Type: application/json" \
  -d '{"text": "Is this a crap email abcdef@abcd.com?", "categories": ["Hate", "Sexual", "SelfHarm", "Violence"], "outputType": "FourSeverityLevels"}'

Content Safety returns categoriesAnalysis (for example {"category": "Hate", "severity": 2}) and blocklistsMatch. Text severities are 0, 2, 4, 6 (four levels) or the full 0–7 scale (eight levels) (harm categories).

FAQ

Is Azure Content Safety the same API as Content Moderator?

No. Content Safety uses POST /contentsafety/text:analyze with a JSON body and returns severity levels for Hate, Sexual, Violence and SelfHarm. Content Moderator's ProcessText/Screen took a raw text body and returned Terms, PII and Classification scores.

Does Content Safety detect PII like Content Moderator did?

Not in text:analyze. Microsoft's guide moves PII detection to Azure AI Language. A wire-compatible replacement can keep the old PII field (email, IP, US/UK phone, US SSN, US address).

How do Content Moderator categories map to Content Safety?

Roughly: Category1 (sexually explicit) and Category2 (suggestive) relate to Sexual, and Category3 (offensive) overlaps with Hate and Violence. The scales differ (0–1 scores versus severity levels), so thresholds must be re-tuned on your own data.

When does Azure Content Moderator stop working?

Microsoft's Content Moderator documentation says March 15, 2027, while its lifecycle table lists April 1, 2027. Plan for March 15 and check the notice for your subscription.

Can I keep using ProcessText/Screen after the retirement?

Not on Azure. A wire-compatible replacement accepts the same ProcessText/Screen request and returns the same JSON from a new host.

What replaces Content Moderator video moderation and the review tool?

Video has no direct replacement. Microsoft suggests extracting frames and sending them to the image API. The Review API and human review tool move to Content Safety Studio, which is a different workflow.
