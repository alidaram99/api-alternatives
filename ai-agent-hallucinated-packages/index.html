Stop AI coding agents from installing packages that do not exist

Last updated: October 3, 2026

ExactGround is a free, open-source guard for AI coding agents. It runs as a hook in Claude Code, Codex, Gemini CLI and Cursor. Before an npm, pnpm, yarn, bun, npx, pip, uv, poetry or pdm install command it can parse runs, it checks each package name against the public npm registry and PyPI. Names that do not exist, versions that were never published, and young look-alikes of popular packages are blocked. Source and install: github.com/alidaram99/exactground.

Why agents need this

A USENIX Security 2025 study (Spracklen et al.) had 16 models write 576,000 code samples. Of the 2.23 million package recommendations in them, 440,445 (19.7%) named packages that do not exist, 205,474 unique names. In a separate test, the authors re-ran 500 prompts that had produced a hallucination 10 times each, and 43% of those hallucinated names came back in all 10 runs (paper). Because the names are predictable, attackers can register them with malware. This is called slopsquatting.

A rule in CLAUDE.md or AGENTS.md saying "never invent packages" is text the model may ignore. A hook is code that runs on every install.

Try it in one line

console
$ npx -y github:alidaram99/exactground#v0.1.3 check pypi:requests pypi:reqeusts react@99.0.0
OK      pypi:requests
BLOCK   pypi:reqeusts — "reqeusts" does not exist on PyPI; did you mean "requests"? (it is 1 edit away)
BLOCK   react@99.0.0 — version 99.0.0 of "react" was never published (latest is 19.3.0)

Install it in your agent

  • Claude Code: claude plugin marketplace add alidaram99/exactground, then claude plugin install exactground@exactground-marketplace.
  • Codex: codex plugin marketplace add alidaram99/exactground --ref v0.1.3, then trust the hook in /hooks.
  • Gemini CLI and Cursor: exactground init gemini --write or exactground init cursor --write in your project.

Installs hidden inside node -e, python -c, $(...) or eval cannot be checked, so the hook denies them. If the registry or the checker fails, it denies too.

Threat model, plainly: ExactGround stops an agent that hallucinates or mistypes a package name in a normal install command. It is a cooperative guardrail, not a sandbox: an agent that deliberately tries to evade it (by writing its own scripts, editing files the hooks do not see, or running code another way) can get around it. To contain an agent you do not trust, use OS or container sandboxing.

Bare installs such as npm install, uv sync and poetry install are checked against the lockfile, so a dependency the agent wrote into package.json or pyproject.toml is caught too.

Check that an API exists in your exact version

Many hallucinations are real packages used wrongly. useActionState does not exist in React 18, and numpy.asfarray was removed in NumPy 2.0. The hosted ExactGround API answers these questions from the published package itself:

  • npm: .d.ts declarations, read with the TypeScript compiler.
  • Python: wheels, parsed statically and never executed.
