Content Moderator retires on 15 March 2027. Keep ProcessText/Screen.

Last updated: October 4, 2026

⏳ 157 days left — the old API shuts down March 15, 2027.

Yes: Microsoft deprecated Azure Content Moderator in February 2024 and retires it on March 15, 2027; its successor, Azure AI Content Safety, is a different API with different requests and results (Microsoft Learn). To keep code that reads Terms, PII and Classification, point your ProcessText/Screen calls at a wire-compatible endpoint such as our Content Moderator drop-in on Apify: same request, same JSON, $1 per 1,000 texts.

Microsoft's lifecycle page lists the retirement as April 1, 2027 (06:59 PT). The product notice says March 15, 2027, so plan for March 15. If you prefer to move to Content Safety, see Content Moderator vs Content Safety: what changes.

What changes on March 15, 2027

  • Existing Content Moderator resources stop being supported. Microsoft has deprecated the service since February 2024, so plan no new work on it.
  • POST https://<region>.api.cognitive.microsoft.com/contentmoderator/moderate/v1.0/ProcessText/Screen and the SDKs built on it (Microsoft.Azure.CognitiveServices.ContentModerator, azure-cognitiveservices-vision-contentmoderator) lose their service.
  • Code, stored results and dashboards that depend on Terms, PII, Classification.Category1/2/3, ReviewRecommended or Status.Code 3000 have no equivalent in Content Safety. It returns severity levels for Hate, Sexual, Violence and SelfHarm instead.

The minimal migration: host and key only

The new endpoint is the Actor's Standby URL, https://dropin-apis--content-moderator-compat.apify.actor. Authenticate with your Apify API token as Authorization: Bearer … (or ?token=…). An Ocp-Apim-Subscription-Key header is accepted and ignored. Path, query string, raw-text body and response are unchanged.

FAQ

Is Azure Content Moderator being retired?

Yes. Microsoft deprecated it in February 2024 and retires it on March 15, 2027. Microsoft's lifecycle table lists April 1, 2027, but the product notice says March 15, 2027, so plan for March 15.

What replaces Azure Content Moderator?

Microsoft's replacement is Azure AI Content Safety, which uses a different API: text:analyze with severity levels for Hate, Sexual, Violence and SelfHarm. To keep the old ProcessText/Screen request and JSON, use a wire-compatible endpoint such as this page's drop-in.

How do I migrate from Azure Content Moderator without rewriting code?

Change the host from <region>.api.cognitive.microsoft.com to the drop-in's Standby URL and send your Apify token as Authorization: Bearer … instead of Ocp-Apim-Subscription-Key. The path, query parameters, body and response JSON stay the same.

Should I just move to Content Safety?

If you can rewrite the integration and re-tune thresholds, yes, that is Microsoft's supported path. This replacement is for teams whose code, stored results and dashboards depend on the old response format.

Are custom term lists supported?

No. The drop-in supports the built-in profanity list (ListId 0), PII and classification. Custom term lists, image and video moderation are not supported.

Do you store text?

No. Nothing is written to disk or logged.

How are short non-English texts handled?

Latin-script text under 40 characters is treated as English. Pass language=spa, language=deu and so on to use the right profanity list.
