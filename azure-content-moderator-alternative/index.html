Content Moderator's text screen retires 15 March 2027. Same request, same JSON.

Last updated: October 3, 2026

⏳ 163 days left — the old API shuts down March 15, 2027.

Microsoft's Content Moderator overview says the service has been deprecated since February 2024 and retires on March 15, 2027. The product lifecycle page lists April 1, 2027. The suggested successor, Azure AI Content Safety, is a different API with a different URL, request and response (severity levels for Hate/Sexual/SelfHarm/Violence). Code that reads Terms, PII and Classification.Category1/2/3 has to be rewritten.

This page shows a wire-compatible replacement for the text screen endpoint, so that code keeps working. You call the same POST /contentmoderator/moderate/v1.0/ProcessText/Screen with the same query string and raw-text body, and get back the same response JSON.

What changes in your code

  1. The endpoint: https://<region>.api.cognitive.microsoft.com becomes https://dropin-apis--content-moderator-compat.apify.actor.
  2. Authentication: send your Apify API token as Authorization: Bearer … or ?token=…. An Ocp-Apim-Subscription-Key header is accepted and ignored.

curl

bash
curl -s -X POST "https://dropin-apis--content-moderator-compat.apify.actor/contentmoderator/moderate/v1.0/ProcessText/Screen?language=eng&classify=True&PII=True&token=$APIFY_TOKEN" \
  -H 'Content-Type: text/plain' \
  --data-binary 'Is this a crap email abcdef@abcd.com, phone: 6657789887, IP: 255.255.255.255, 1 Microsoft Way, Redmond, WA 98052'

That is Microsoft's own documentation example. Our response matches Microsoft's published NormalizedText, the Terms entry (crap at Index 10) and every PII index:

C# (HttpClient, .NET 6+)

csharp
using System.Net.Http.Headers;
using System.Text;
using System.Text.Json;

var baseUrl = "https://dropin-apis--content-moderator-compat.apify.actor";
var token = Environment.GetEnvironmentVariable("APIFY_TOKEN")!;

using var http = new HttpClient();
http.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", token);

var content = new StringContent("Is this a crap email abcdef@abcd.com?", Encoding.UTF8, "text/plain");
var response = await http.PostAsync(
    $"{baseUrl}/contentmoderator/moderate/v1.0/ProcessText/Screen?language=eng&classify=True&PII=True", content);
response.EnsureSuccessStatusCode();

using var json = JsonDocument.Parse(await response.Content.ReadAsStringAsync());
var root = json.RootElement;
Console.WriteLine($"Status {root.GetProperty("Status").GetProperty("Code").GetInt32()}, " +
                  $"Category3 {root.GetProperty("Classification").GetProperty("Category3").GetProperty("Score").GetDouble():F3}, " +
                  $"first term '{root.GetProperty("Terms")[0].GetProperty("Term").GetString()}'");
// Status 3000, Category3 0.971, first term 'crap'

If you use the old Microsoft.Azure.CognitiveServices.ContentModerator SDK, set client.Endpoint to the Standby URL and pass ServiceClientCredentials that add the Authorization: Bearer header. We tested the REST path above, not that SDK.

Python (requests)

python
import os
import requests

BASE = "https://dropin-apis--content-moderator-compat.apify.actor"
APIFY_TOKEN = os.environ["APIFY_TOKEN"]

r = requests.post(
    f"{BASE}/contentmoderator/moderate/v1.0/ProcessText/Screen",
    params={"language": "eng", "classify": "True", "PII": "True"},
    headers={"Content-Type": "text/plain", "Authorization": f"Bearer {APIFY_TOKEN}"},
    data="This is crap, email me at someone@example.com".encode("utf-8"),
)
screen = r.json()
print(screen["Status"]["Code"], screen["Classification"]["Category3"]["Score"],
      [t["Term"] for t in screen["Terms"] or []], [e["Text"] for e in screen["PII"]["Email"]])
# 3000 0.98 ['crap'] ['someone@example.com']

What is identical, approximate, or unsupported

FeatureStatus
Route, method, query parameters (case-insensitive), text/plain/html/xml/markdown bodies, 1,024-character limitIdentical
Field names, casing and order; Status 3000; Terms: null when clean; Misrepresentation: null; TrackingIdIdentical
NormalizedText; Terms Index and OriginalIndex offsetsIdentical on Microsoft's documented examples. Unusual inputs may normalize differently
PII (Email, IPA, Phone, Address, SSN)Same shape. Patterns are deliberately strict: US/UK phones, US addresses with state and ZIP
Built-in profanity list (ListId 0)Same format. The word list is open (LDNOOBW, CC-BY-4.0, 24 languages), so matches can differ from Azure's private list
Classification Category1 (explicit), Category3 (offensive)Approximate. Open Detoxify model; scores differ from Azure's
Classification Category2 (suggestive)Approximate proxy: max(Category1, 0.3 × obscene). Flirty but clean text is not detected
ReviewRecommendedTrue when any category is ≥ 0.5. Azure's own thresholds were never published
Classification for non-English textOmitted, as in Azure
autocorrect=trueAccepted. The field is returned, but no spelling correction is applied
Custom term lists (listId), image/video moderation, list management, review toolNot supported

Pricing

$1 per 1,000 screened texts, pay per event. Requests that fail validation are not charged. There is no subscription, and you can cap spending per run on Apify (429 TooManyRequests at the cap).

FAQ

Should I just move to Content Safety? If you can rewrite the integration and re-tune thresholds, yes, that is a fine path. This replacement is for teams whose code, stored results and dashboards depend on the old response format.

Do you store text? No. Nothing is written to disk or logged.

Short non-English texts? Latin-script text under 40 characters is treated as English. Pass language=spa, language=deu and so on to use the right profanity list.
